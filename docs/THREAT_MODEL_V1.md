# Personal Live V1 threat model

Status: proposed controls awaiting human review, 2026-09-07. This is a code/design review and scoped privacy audit, not penetration-test certification. V1 is single-owner and loopback-only; hosted exposure is not approved. Proposed controls below are not claims of implemented protection.

Public assets: source, fictional fixtures, safe documentation and CI. Private local assets: profile/version snapshots, SQLite/WAL/backups, real vacancies/URLs, answers/notes, CVs/letters, browser sessions and receipts. External boundaries: source APIs/pages, employer forms and optional future providers. Candidate data must not cross a boundary because an ad contains a URL or instruction.

Threat actors include malicious files/sites/ads, cross-origin websites targeting loopback, compromised dependencies/accounts, accidental publication, other local users and malware. Likelihood is qualitative L/M/H before planned mitigation. Residual risk assumes tests pass; missing controls remain open blockers.

## Mandatory gates

R2 fixes truth/verification/provenance defects before trusted ranking. R3 enforces all-field claim/layout/path guards. R5 requires local-origin/session controls, approved session key storage, disclosure/destination restrictions and final-action tests before real filling. R8 requires zero unresolved critical/high exposure or irreversible-action defects, current dependency review, backup/restore drill and build/privacy audit. R10 needs a separate internet-facing authentication/authorisation/pairing/retention/residency design and independent security review.

These are defensive requirements, not claimed exploits. No live external target or unrelated local service was attacked. If sensitive publication is found, stop pushes/releases, report only paths/commits privately, preserve evidence and ask the owner about remediation. Credential revocation, visibility reversal, history rewrite and private-data deletion need appropriate separate authority; public copies cannot be recalled.
