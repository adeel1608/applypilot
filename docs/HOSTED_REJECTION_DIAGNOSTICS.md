## Diagnostic contract and historical limits

Implementation will use strict version1 metadata on the existing stop audit, without a migration. Enums, booleans/null and capped counters only; no destination value or hash, header/body/file/candidate content, arbitrary exception text or stack. First-observed evidence is immutable except capped secondary counters; it is not necessarily the physical root cause. Proxy resource/frame fields remain UNKNOWN. Native phases are observed within the pinned transport; an injected fictional transport cannot establish native DNS/socket/header/body phases.

Submit also has a returned-result path: driver returns OUTCOME_UNKNOWN/safeStopCode; service persists completion rather than calling stop. Its optional diagnostic must cross that result/evidence path and the existing HOSTED_OPERATION_COMPLETE audit. Read the earliest terminal audit only. Persist before cleanup and never amend a terminal audit for later secondary events. `routeAttemptCount` describes the local pre-budget/pre-onRequest increment, distinct from the durable session request count. Browser URL normalization limits what shape flags can be observed; explicit low-level request tests cover removed URL components without claiming a browser sent them.

Legacy stops remain code-only and display `DIAGNOSTIC_NOT_RETAINED`. Neither historical employer stop has retained evidence identifying its emitting site. Offline structural reproduction cannot fill that gap. Source question discovery remains distinct from native form inventory. Tests, release results and rollout identities will be recorded after execution; this blueprint does not claim them.

## Implemented contract

`HostedRejectionDiagnosticSchema` in application-runner/hosted-diagnostics.ts is strict at construction, repository persistence/readback and UI rendering. All nested objects reject additional keys. Schema version1 carries the existing closed safe code, site/stage/method/resource enums, nullable observation booleans, exact approved-entry match booleans, five URL-shape flags, five transport validity flags, an observed transport phase and counts capped at1000. No destination value or hash is retained. `routeAttemptCount` is the driver's increment before budget/onRequest, not the durable request count. Proxy metadata is uncorrelated and stays UNKNOWN. Native socket observation means an actual Node socket event, not successful TLS or remote acceptance. Fictional injected transport phases stay UNKNOWN.

The driver recorder preserves the first rejection it observes at a route catch, proxy callback or explicit driver fence. Secondary events only increment bounded secondary counters. The native transport separately freezes its first failure phase at the rejecting event, so later socket/header/end events cannot inflate that evidence before promise propagation. Neither ordering is claimed to reconstruct a physical root cause. Zod parsing clones input/snapshots to prevent later mutation. Stop/completion metadata is a snapshot taken before browser cleanup; later events do not rewrite it.

Secondary proxy counts use an explicit directly observed callback flag. A later route aborted by an inherited prior proxy error increases only the secondary rejection count; its inherited site does not establish another proxy denial. The initial implementation's contrary count was reproduced offline and repaired before acceptance, with a prior-proxy/route/actual-proxy ordering regression.

Service failures preserve original safe evidence when optional diagnostics or cleanup fail. Audit failure is flagged separately while the existing fallback terminalizes/revokes; writes and activated submits remain OUTCOME_UNKNOWN. A returned submit rejection carries diagnostics through completion. The first terminal audit is the only readback source; code-only, malformed, oversized or unretained evidence displays DIAGNOSTIC_NOT_RETAINED. A later valid audit cannot retrospectively enrich a legacy stop. No schema migration, source policy, capability digest, budget, domain, query handling or owner gate changed.
