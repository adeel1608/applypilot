# R2 evidence contributions, version 2

Eligibility and scorer2.4.0 implement `r2-capability-evidence-2`. This is a deterministic literal contract, not an ontology, semantic similarity system or calibrated probability model.

The full matcher establishes only supported bounded requirements. A credential's level and field must occur on the same VERIFIED education record with the required completion/study state. Skills cannot prove years, recency, seniority, alternative-domain equivalence or the rest of a composite clause. Condition metadata in either the outer or typed value remains unresolved even if a caller supplies REQUIRED modality. Existing currentness, coverage, eligibility, owner qualification and recommendation gates remain separate.

Credential names use directional full-name support, so a generic driving licence cannot prove a Class MR driving licence. An explicit typed licence class remains REVIEW_UNCONFIRMED because the current candidate schema has no validated typed class field; no class equivalence is inferred. Exact forbidden/unsupported credential scope prevents positive admission even if another stored verified row contradicts it. Separate jurisdiction and expiry checks remain. Scoring grants no name-only credit for separate unresolved class/jurisdiction/validity obligations.

The scorer can retain a verified atomic skill explicitly present in a usable SKILL/EXPERIENCE clause as `PARTIAL_EVIDENCE`. This is literal verified evidence overlap, not proof of demonstrated task affinity or whole fit. For example, verified Python is evidence linked to a clause requiring Python and an aircraft credential; it does not establish the credential. A quantified experience clause can contain literal Python evidence while its years remain unconfirmed. No overlap credit is supplied for legal, credential, document, age, physical or education clauses. Unknown, conflicting, negated or conditional source scope is excluded. Explicit source polarity is checked independently of modality metadata. Recruitment/management/trained-others noun contexts do not become direct tool-use evidence.

Positive contributions carry `requirementSupport` links for every counted source. A fact can have preferred FULL support worth4 and required PARTIAL overlap worth7. Its strongest contribution is7, while each source keeps its own mode; the partial source never becomes full. The scorer preserves at most one semantic fact's weight per requirement. When several literal facts overlap, selection uses the ordered semantic key and reference, rather than private outcomes. Repeated uses of that fact count once at the strongest7/4 weight and retain every source link. Distinct supported facts can still outscore one another under the unchanged equal weights; specificity is not assigned a new bonus.

Semantic identity uses the canonical literal skill label; education qualification/field/state; credential name/jurisdiction/class/expiry; or the complete non-ID employment record and title/responsibility position. Identical semantic facts retain all record references without multiplying points. A colliding ID uses `<family>.<escaped-id>.records.<original-index>`; reserved delimiters are encoded to prevent another ID from impersonating that reference. The unchanged profile version/hash binds the original ordering and bytes. No profile repair or new candidate assertion occurs.

The only named-language grammar removes terminal `programming` for closed literal identifiers: C++, C#, F#, .NET, Python, Java, JavaScript, TypeScript, Rust, Ruby, Swift, Kotlin and SQL, preserving exact numeric versions. It maps no abbreviation to another name. Ambiguous bare C/Go/R retain exact-label conservatism. Robotics programming cannot become full robotics support. Malformed punctuation, dotted variants and versions remain distinct. Exact Basic Python can match that same explicit level, but cannot establish advanced or unqualified scope. A verified affirmative direct-use sentence can supply its exact whole tool-use object; recruitment or a word embedded in a role title cannot establish a skill. Candidate-side terminal `without supervision` on affirmative direct use does not negate the use, and supplies no inferred independence to a different fact.

Unsupported claims use directional scope and punctuation-preserving tokens. Unrelated cash-handling cannot deny C++, and an inflated forbidden expert claim does not erase a separately verified basic identity. Direct unsupported scope still blocks positive admission and remains an explicit conflict. The existing negative-constraint repetition policy is unchanged.

`evidenceOpportunity` contains disjoint source-ID sets for full support, partial evidence, and no accepted match among usable requirements, plus excluded evidence. These are raw evidence states, not percentages of ability or readiness. Repeating a clause can increase occurrence counts without increasing score. Stale bindings clear positive contributions and expose only excluded opportunity. Scores remain absolute additive0..100 with no sparse-description rescaling. Preferred partial evidence can affect the score when mandatory eligibility is otherwise established; it never implies that all preferred scope is satisfied. Recommendation still independently requires ELIGIBLE, current bindings, no material unresolved states, minimum coverage60 and score50.

Fictional tests cover exact identifiers, malformed versions, same-record education, conditions, mixed support modes, duplicate/colliding references, direct-use scope, negative claims, reorder/repetition and stale bindings. This release preserves existing assessment and owner-gate semantics. Historical records remain unchanged; separately versioned comparisons do not create or reinterpret owner judgments.
