## Required process

PLAN -> OWNER-DELEGATED AI PLAN REVIEW -> IMPLEMENT -> TEST -> AI TECHNICAL REVIEW -> GUARDED MERGE -> FRESH MERGED-BUILD VALIDATION -> SEALED ROLLOUT.

- Pass A inspects correctness, integration, tests and regressions. Pass B inspects adversarial security, privacy, failure recovery and release gates. Both cover the entire cumulative changed scope beginning at `ad61cbaf2327d99547306801e3d22d0cba4717c1`, including PR79 and every policy/fix commit. Read all changed code/tests and complete critical functions/callers. Record per-file Git-blob coverage. Review generated lockfiles through package/version/integrity/manifest consistency, without claiming dependency source-byte auditing.
- Prefer separate read-only AI agent executions. A same-agent second pass is allowed only with its explicit `SAME_AGENT_SECOND_PASS` label, the same execution identity and linkage to the first pass. Neither mode is independent human review. Record actual modes/identities and completion timestamps; unknown model identity remains UNKNOWN.
- Report severity, location, reproduction/evidence, impact and disposition. Resolve every blocking or high/critical finding and re-review affected final code. A status check or code summary is not a technical review.
- Freeze code before publishing final reports. Each actual report binds exact base/head/tree, policy/delegation, the complete ordered file manifest and its digest, pass purpose/identity, findings, validation references and decision. Publish it after the code commit as a submitted GitHub COMMENTED review labelled `AI-AUTHORED TECHNICAL REVIEW UNDER OWNER-DELEGATED POLICY`. Reports are outside the attested code tree, avoiding a self-hash loop. Never post a human approval phrase or self-APPROVE.

## Enforcement and trust boundary

The canonical sealer retrieves the selected submitted review bodies and metadata from GitHub. Only the authorized owner publishing account `adeel1608` is trusted to publish delegated execution evidence; arbitrary visitor reviews do not qualify. A GitHub User account does not prove human authorship. AI reports never increment human counts or silently clear effective change requests. Full review history and unresolved threads remain blocking.

Schema2 seals require two distinct actual reports/purposes, exact current PR head and squash-merge tree equality, current fixed policy/delegation, complete cumulative Git-blob coverage, no unresolved blocking findings, successful actual-merge CI, fresh frozen quality evidence, actual compiled bytes/BUILD_ID/quality digests, and healthy migrated canonical state. Ancestor checks alone are insufficient. Startup/runtime/staging/readiness revalidate the cached retrieved reports, policy, scope and current executable bytes without a per-operation GitHub request. Historical schema1 human-reviewed records retain their original validation semantics.

A content digest proves consistency, not independent authorship or that a model actually read a file. This single-owner local environment trusts the explicit owner delegation, the authorized publishing account and the actual recorded agent process. It has no new signing infrastructure and makes no stronger assurance. A bare `{approved:true}`, positive counter, missing report, changed policy, stale head/tree or narrowed scope cannot satisfy the production gate. Tests use explicitly fictional review transport and disposable Git/DB/build state; fictional artifacts must never be published or installed in the canonical runtime.

New AI seals require version2 frozen quality evidence. Its production digest binds all `.next/server` and `.next/static` files, BUILD_ID and root runtime JavaScript/JSON manifests, including required-server-files.json and build-manifest.json. Mutable caches, development output, logs, diagnostics and generated types are excluded. Legacy version1 quality and human-reviewed records retain their historical server-only hashing semantics. Installed Node/runtime/dependency bytes remain within the local-owner trust boundary; this digest does not claim to attest the entire machine.
